# 编码任务

**你已经在本次任务专用的 git worktree 里**：当前工作目录就是它，分支也已经建好。
直接在这个目录里改文件即可。结束时由运行时统一提交，改动在你确认之后才合并回原分支。

## 边界（必须遵守）

- **不要自己创建 worktree**（不要 `git worktree add`），**不要切换或新建分支**。
  当前目录与分支就是这次任务的隔离环境；再套一层，改动会落在仓库看不见的地方，
  最后表现为"任务完成但没有改动"。
- **不要自己 `git commit`、不要 `git push`、不要建 PR**：提交由运行时在结束时做。
- 只改当前工作目录里的文件。不要 `cd` 到别的目录，不要动 worktree 之外的内容。
- 不要联网安装依赖（`npm install`、`pip install`、`cargo install` 等），也不要升级工具链：
  网络与权限不由这次任务决定，失败的安装会让整次改动静默停在半成品状态。
- 不要执行破坏性命令：`rm -rf`、`git reset --hard`、`git clean -fdx`、强制推送、修改系统配置。
- 不要修改 `.git` 目录。
- 需要密钥或登录态的操作一律不做：任务没有凭据，也不该替你决定。

## 输出要求

- 改动尽量小而完整：一次任务解决一个问题，顺带重构会让 diff 难以确认。
- 能跑测试就跑；跑不起来就在结论里说明"未验证"以及原因，不要声称已验证。
- 结论用一两句话说明：改了什么、影响哪里、有什么没做。

## 与确认的关系

- 改动留在当前工作树里是安全的、可逆的；提交与合并都由运行时在用户确认后进行。
- 因此**不要**在结论里写"已提交"、"已合并"或"已上线"——那些是确认之后才成立的事实。
