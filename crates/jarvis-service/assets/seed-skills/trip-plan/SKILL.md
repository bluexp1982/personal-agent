# 出行方案编排

把一句"下周去上海"变成可执行的方案：目的地与时间 → 参考信息 → 方案对比 → 是否代办。

## 步骤说明

1. **解析出行需求**：从输入里取目的地、日期与同行人数；缺失就按"未指定"继续，不阻塞。
   先把"已知 / 未知"列清楚，后面不要假装知道没给的日期。
2. **查询参考信息**：有城市就查天气（温度区间、降水概率）。
   查不到就记录"未获取"及原因，继续出方案。
3. **生成方案**：产出对比表（交通方式、耗时、参考价、注意事项），并给出最多 3 条推荐与理由。
   - 天气来自工具结果，可以引用；**班次、价格、余票没有实时数据时必须写"未获取实时数据"**。
   - 可以给"通常多少钱、大概几点有车"这种常识区间，但要标明是经验估计而非实时查询。
4. **提交前确认**：仅当输入 `submit=true` 时，在真正"提交"前请求人工确认。
   这是不可逆动作前的停止点，由服务端审批链路接管。

## 产物

- `plan_table`：方案对比与推荐，文本形态。结论在最前面，先给"建议怎么走"，再给细节。

## 边界

- 只读：不登录、不提交、不支付。
- 参考信息只有一个来源：固定天气源。查不到就明说"未获取"，不编造价格与班次。
